## 摘要
驾驶视频生成模型通过预测可控的未来场景来支持自动驾驶开发，用于仿真、规划评估和离线数据生成。基于扩散的驾驶生成器在去噪步骤中反复评估大型骨干网络，这限制了生成吞吐量。现有的扩散加速方法降低了这一成本，但通用设计忽略了生成前可获得的驾驶信号，如自车速度和规划轨迹。跨驾驶动作的实验表明，缓存容差随自车平移和旋转、去噪进度以及连续重用长度而变化。我们提出了DriveCache，一种无需训练的动作感知控制器，利用规划运动在场景间分配重用，并通过动态规划在校准的响应预算下跨去噪步骤放置重用。因果漂移检查在生成偏离校准时刷新特征并重新规划剩余调度。在三种生成器配置下，DriveCache在整体保真度-效率权衡上优于所评估的缓存方法。我们的代码将公开提供。

## Abstract
Driving video generation models support autonomous-driving development by predicting controllable future scenes for simulation, planning evaluation, and offline data generation. Diffusion-based driving generators repeatedly evaluate large backbones across denoising steps, which limits generation throughput. Existing diffusion acceleration methods reduce this cost, but general-purpose designs omit driving signals available before generation, such as ego speed and planned trajectories. Experiments across driving motions show that cache tolerance varies with ego translation and rotation, denoising progress, and consecutive reuse length. We propose DriveCache, a training-free, action-aware controller that uses planned motion to allocate reuse across scenes and dynamic programming to place it across denoising steps under a calibrated response budget. A causal drift check refreshes features and replans the remaining schedule when generation departs from calibration. Across three generator configurations, DriveCache improves the overall fidelity-efficiency trade-off over evaluated cache methods. Our code will be publicly available.

### 2. 论文提出的方法论

**核心思想**

- DriveCache 的核心洞察在于：**规划的自车运动（平移与旋转）能够作为生成前的场景级缓存容差先验信号**——低速直行场景容忍更多缓存重用，而高速转弯场景则需要更少的重用，以避免视角变化导致的画面失真。
- 方法整体框架包括四个阶段：**双锚点运行校准 → 规划运动插值 → 精确动态规划调度 → 因果漂移检查**。

**关键技术细节**

1. **规划运动量化**：对生成范围内规划的自车平移（Ls）和旋转（Θs）进行标准化，分别计算总平移距离和累积旋转角度。
2. **双锚点校准**：
   - 低运动锚点（L0, Θ0）：最小化标准化平移与旋转之和，代表高缓存容忍度场景。
   - 动态转弯锚点（L1, Θ1）：在满足条件中最大化标准化乘积，代表低缓存容忍度场景。
3. **场景支持与插值**：通过坐标门控判断场景是否在校准支持域内（超出则全推理回退），再通过插值系数 Ds 融合两个锚点的缓存响应，生成针对该场景的预测。
4. **联合运行响应建模**：
   - 定义了输入漂移（input drift）和输出扰动（signed output perturbation）。
   - 通过冻结采样器的雅可比-向量积（Jacobian-vector products）将整个缓存重用过程传播到终端隐变量，得到联合终端响应（joint terminal response），这一方法**捕获了跨步骤的误差抵消与放大效应**（见图6、7）。
   - 通过单调包络（monotone envelope）和增量运行成本（incremental run cost）转换为调度可用的代价函数。
5. **精确动态规划（DP）**：
   - 在响应预算 τ 下，通过递推关系 Jk+1(n, h) 精确求解最大化去噪步骤中的重用数量，同时满足模型特定的合法性约束（如专家路由边界、自回归段边界）。
   - 时间复杂度 O(K³)，内存 O(K²)，可直接回溯得到最优调度。
6. **因果漂移检查（Causal Drift Check）**：
   - 在每次计划重用前，测量实际输入漂移是否超过校准阈值；若超过，则强制刷新缓存并**对未执行的后缀重新规划**，已执行前缀保持不变。
   - 这一机制确保生成偏离校准时能够及时修正，保持因果性。

### 6. 论文的主要结论与发现

- 规划的自车平移与旋转是预测场景级缓存容忍度的有效预生成信号，跨不同驾驶动作均成立。
- DriveCache 在 Wan2.2 5B 上达到 **1.84× 加速比、34.744 dB PSNR**；在 A14B 上达到 **1.97× 加速比、32.778 dB PSNR**。
- 在约 2× 加速下，较 TeaCache 在 A14B 上 PSNR 提升 **2.036 dB**；较 SeaCache 在 5B 上提升 1.884 dB（95% CI: 1.61–2.15）。
- 在 Epona 上达到 **1.89× 加速比**，LPIPS 为 0.140，优于 DeepCache 的 1.68× 加速比，且在静止场景增益更大、转弯场景行为更保守。
- 轨迹质量（Traj.）、DTW 等下游指标同步改善，说明缓存调度优化并不牺牲驾驶行为一致性。
- 消融表明：运动先验贡献 > 动态规划放置 > 漂移否决；将复用移入 A14B 高噪声专家会显著降低质量，专家边界约束比更稠密的插值更重要。

### 8. 不足与局限

- **模型覆盖面有限**：仅评估了 Wan2.2 系列和 Epona 三种生成器配置，未覆盖更多开源驾驶世界模型（如 MagicDrive、 Vista、DriveDreamer 等）。
- **同步相机与简单运动假设**：实验数据（DrivingGen、nuScenes）以同步相机和常规驾驶动作为主，未涉及极端运动（急刹车、剧烈变道、非结构化场景）或异步相机设置。
- **支持域门控的限制**：约 3.6% 的场景落入支持域之外而回退至全推理，方法对超分布场景的泛化能力有限。
- **位姿噪声鲁棒性仅在单一幅度下评估**：1.0 m/5° 噪声下的表现能否推广到更大的规划误差或感知噪声有待进一步验证。
- **校准过程存在先验依赖**：双锚点与阈值基于校准集生成，虽然未接触评测集，但锚点选择机制本身可能隐含对特定运动分布的先验偏好。
- **量化误差未充分讨论**：虽然从计算层面匹配了加速比，但对缓存导致的端到端生成质量误差的分布属性（如最差场景性能）讨论不足——表1中 LPIPS 在部分设置下仅与基线持平，提升主要体现在 PSNR 和轨迹指标上。
- **未提及多卡并行或批处理场景**：实验以 batch size 1 为基准，高吞吐批处理场景下缓存策略的适用性未经考察。
