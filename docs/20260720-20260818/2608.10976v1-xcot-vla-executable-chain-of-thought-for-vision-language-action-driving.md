## 摘要
视觉-语言-动作（VLA）模型能够连接自动驾驶中的场景理解、语义推理和轨迹生成。然而，冗长的自然语言思维链（CoT）并不适合实时控制，因为它是开放式的、解码成本高，并且难以作为面向动作的表示进行优化。我们提出了XCoT-VLA，它用从自动构建的推理-动作监督中学习到的紧凑可执行CoT标记取代了描述性理由。记录的轨迹提供动作证据，而场景上下文提供因果语义。预测的XCoT序列保持在上下文中，并通过共享的多模态自注意力为固定的轨迹查询提供条件。确定性令牌-函数路由将推理FFN应用于XCoT令牌，将控制FFN应用于轨迹查询，以进行流匹配轨迹生成。我们进一步引入了XCoT策略优化（XCPO），作为同一可执行令牌空间中的可选细化扩展。XCoT-VLA在一般分布集上将纵向ADE从1.645降低到1.323，在变道场景中将横向FDE从1.616降低到0.648。通过仅使用2-6个可执行XCoT令牌来表示面向驾驶的推理，我们的方法大幅减少了自回归推理开销，并保持在实时规划预算之内。这些结果表明，面向驾驶的推理可以紧凑、可执行，并直接与轨迹生成相连。

## Abstract
Vision-Language-Action (VLA) models can connect scene understanding, semantic reasoning, and trajectory generation for autonomous driving. However, verbose natural-language Chain-of-Thought (CoT) is poorly suited to real-time control because it is open-ended, costly to decode, and difficult to optimize as an action-facing representation. We propose XCoT-VLA, which replaces descriptive rationales with compact executable CoT tokens learned from automatically constructed Reason-Action supervision. Logged trajectories provide action evidence, while scene context supplies causal semantics. The predicted XCoT sequence remains in context and conditions fixed trajectory queries through shared multimodal self-attention. Deterministic token-function routing applies the Reason FFN to XCoT tokens and the Control FFN to trajectory queries for flow-matching trajectory generation. We further introduce XCoT Policy Optimization (XCPO) as an optional refinement extension in the same executable token space. XCoT-VLA reduces longitudinal ADE from 1.645 to 1.323 on a general-distribution set and lateral FDE from 1.616 to 0.648 in lane-change scenarios. By representing driving-oriented reasoning with only 2-6 executable XCoT tokens, our method substantially reduces autoregressive reasoning overhead and remains within the real-time planning budget. These results demonstrate that driving-oriented reasoning can be compact, executable, and directly connected to trajectory generation.

## 1. 核心问题与整体含义

- **研究动机**：Vision-Language-Action（VLA）模型虽能将场景理解、语义推理与轨迹生成结合，但现有方法普遍采用**冗长的自然语言 CoT** 作为中间推理接口。自然语言 CoT 存在三个根本问题：
  1. **开放无边**：自由形式的理由常包含与即时决策无关的信息，难以聚焦于关键驾驶意图。
  2. **解码成本高**：逐 token 自回归解码带来显著额外延迟，难以满足自动驾驶实时规划预算（如 12 Hz 对应 83.3 ms）。
  3. **难以面向动作优化**：语言学结构与可执行运动之间缺乏直接映射，不易与轨迹生成联合优化。
- **核心问题**：驾驶 VLA 模型到底需要什么样的推理形式？作者认为，暴露给轨迹生成器的推理应当满足 **决策关键、紧凑、可执行** 三个性质，而非简单地向“是否该推理”做二元回答。
- **整体含义**：提出 XCoT（Executable Chain-of-Thought），用 2–6 个可执行的语义动作 token 替代 40–80 个自然语言 token，实现低延迟、可优化、直接连接轨迹生成的驾驶推理接口。

## 2. 方法论

### 2.1 核心思想

- **XCoT token 表示**：将驾驶推理压缩为短序列的、属于固定可解释词表的语义动作 token，如 `LEFT_TURN_PREPARE`、`DECELERATE`、`RED_LIGHT_HOLD` 等。这些 token 编码决策关键的驾驶意图，并直接条件化后续轨迹生成。
- **监督构造链条**：
  `(o_t, τ_t) → fact → a_t → fground → (r_t*, a_t) → gXCoT → z_t*`
  即以“记录轨迹 + 场景上下文”为输入，先生成 Reason–Action 对（动作证据 + 因果语义），再通过语义压缩映射为规范化的 XCoT 序列。

### 2.2 关键组成部分

- **Reason–Action 监督构造**：
  - 从记录轨迹中提取纵向与横向动作证据（速度、加速度、车道相对位移、轨迹几何）。
  - 在场景上下文中生成候选原因（导航意图、道路结构、交通规则、交互、安全），并利用多个视觉语言专家的共识得分选出最一致的原因。
  - 语言仅作为离线因果监督来源，最终 token 化由规范化的语义压缩函数 `gXCoT` 完成。
- **解耦的推理–控制架构**：
  - 所有 token 先通过共享的多模态自注意力交互。
  - 之后采用**确定性 token-函数路由**：所有非轨迹 token（包括 XCoT）进入 Reason FFN，24 个轨迹查询 token 进入 Control FFN；两个分支互斥且覆盖全部有效位置。
  - 这种设计与 MoE 不同，无需学习路由，天然隔离推理与控制的计算路径。
- **轨迹生成**：使用 **条件流匹配（CFM）**，每条轨迹查询对应未来一个时间步，预测纵向加速度与横摆角变化对 `(a_lon, Δψ)`，共 24 步，再通过时间积分得到坐标轨迹。
- **Stage I（监督微调）**：联合优化 XCoT token 预测的交叉熵损失与流匹配损失：`L_SFT = λ_XCoT L_XCoT + λ_FM L_FM`。训练时 teacher-forcing 真值 XCoT 标签，推理时使用自回归预测的序列。
- **Stage II（XCoT 策略优化 XCPO，可选）**：
  - 冻结视觉编码器、共享自注意力、Control FFN 及轨迹解码器，仅更新 Reason FFN 和 XCoT 预测头。
  - 从旧策略采样一组 XCoT 序列，经冻结执行器解码得到轨迹，计算组内相对优势 `A_i`，使用类似 GRPO 的 clipped 目标 + KL 正则优化。
  - XCPO 仅作用于离散 XCoT 空间，当前版本未作定量评估。

## 6. 主要结论与发现

- **XCoT 有效提升开环规划精度**：在 General 集上，纵向 ADE-6s 从 1.6452 降至 1.3233，纵向 FDE-6s 从 4.3541 降至 3.0887；在 Lane-change 集上，横向 ADE-6s 从 0.5941 降至 0.3091，横向 FDE-6s 从 1.6160 降至 0.6484。
- **可执行推理优于自然语言与无语义潜变量**：Verbose CoT 在横向精度上不升反降，Latent tokens 虽有帮助但弱于完整的 Reason–Action 监督。
- **XCoT 显著降低推理延迟**：2–6 个 token 在 2K–6K 输入长度下均低于 12 Hz 预算（最坏 66.3 ms），而 Verbose CoT（40–80 token）全面超标（最坏 306.8 ms）。
- **解耦微调优于联合微调**：Decoupled XCoT FT 避免 Joint FT 出现的严重纵向短时退化（ADE-2s-Long 从 0.2774 恶化至 1.1684），并在横向精度上取得改进。
- **定性上更主动、更符合交通语义**：XCoT 在导航前摄变道、交通灯提前减速、效率驱动变道等场景中较 SFT 基线表现更提前、更平滑。

## 7. 优点

- **问题定位精准**：直击自然语言 CoT 在实时控制中的核心矛盾，提出“决策关键、紧凑、可执行”的推理接口设计原则，具有领域普适性。
- **架构设计简洁而有效**：确定性 token-函数路由无需学习路由器，既分离推理与控制计算路径，又通过共享自注意力保留两者的信息交互，新颖且易实现。
- **数据构造链条完整**：从记录轨迹与场景上下文自动生成监督标签，利用专家共识和语义压缩减少标注噪声，并支持人工标注补充，具有良好的工程可扩展性。
- **实验分析角度多元**：不仅关注精度，还覆盖延迟预算、训练稳定性、定性行为对比等部署相关维度，评估视角务实。
- **结论可信度高**：控制变量设计（相同主干，仅改推理接口）使结果能较干净地归因于 XCoT 本身的贡献。

## 8. 不足与局限

- **实验覆盖不足**：
  - 缺少闭环评估，无法判断在真实交互、安全性和任务完成率上的实际表现；

- **XCoT 表示能力受限**：
  - 不擅长与周围智能体的多轮交互协商；
