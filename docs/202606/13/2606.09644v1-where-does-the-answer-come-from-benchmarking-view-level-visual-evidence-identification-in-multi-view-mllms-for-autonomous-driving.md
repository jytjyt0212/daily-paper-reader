## 摘要
多模态大语言模型在视觉推理基准测试中取得了强劲的结果，但仅凭答案准确性并不能表明模型是否依赖了正确的视觉证据。这一差距在用于自动驾驶的多视图驾驶场景中尤为重要，因为模型可能得出看似合理的答案，却将其基于错误的摄像头视角。我们引入了一个多视图视觉问答基准，用于评估证据来源识别：给定六个同步的NuScenes视图和一个问题，模型必须识别出支持性摄像头视角并回答问题。该基准包含来自73个场景的122个以冲突为中心的问题-答案对，涵盖因果性、反事实推理和意图预测。视图标签由自动冲突挖掘流程提出，并由标注员手动验证。我们评估了三种设置：摄像头视角选择、基于黄金视角的预言问答，以及模型一次性选择视角并回答的联合预测。答案以多项选择和自由形式两种格式进行评估，结构化预测采用精确匹配，自由形式回答使用LLM评判。通过明确将视觉来源识别与答案正确性分离，该基准揭示了仅评估答案所忽略的 grounding 失败。

## Abstract
Multimodal large language models (MLLMs) achieve strong results on visual reasoning benchmarks, but answer accuracy alone does not indicate whether a model relied on the correct visual evidence. This gap is particularly important in multi-view driving scenes used for autonomous driving, where a model can produce a plausible answer while grounding it in the wrong camera view. We introduce a multi-view visual question answering benchmark for evaluating evidence-source identification: given six synchronized NuScenes views and a question, the model must identify the supporting camera view and answer the question. The benchmark contains 122 conflict-centric question-answer pairs from 73 scenes, spanning causality, counterfactual reasoning, and intent prediction. View labels are proposed by an automatic conflict-mining pipeline and manually verified by annotators. We evaluate three settings: camera-view selection, oracle QA given the golden view, and joint prediction in which the model selects a view and answers in one pass. Answers are evaluated in both multiple-choice and free-form formats, using exact match for structured predictions and an LLM judge for free-form responses. By explicitly separating visual-source identification from answer correctness, the benchmark exposes grounding failures that answer-only evaluation misses.

当前多模态大语言模型（MLLM）评估主要关注最终答案的正确性，却忽略了答案是否基于正确的视觉证据。这一缺陷在自动驾驶的多视图场景中尤为突出——车辆、行人等目标可能出现在不同摄像头视角中，模型可能通过语言先验或数据集捷径给出正确答案，但实际依赖了错误的摄像头视图。这种行为反映了不忠实的多视图grounding，可能导致安全隐患。为了诊断这一问题，论文提出了一个专门评估视图级视觉证据识别的基准，明确分离“答案正确性”与“证据来源正确性”。

## 2. 方法论

- **核心思想**：基于NuScenes数据集构建多视图VQA基准，每个实例包含六张同步相机图像（前、前左、前右、后、后左、后右）、一个自然语言问题，以及人工验证的“黄金视图”——即回答问题所需视觉证据所在的相机通道。
- **关键技术细节**：
  - **数据构建**：采用自动冲突事件挖掘流水线，从NuScenes中提取冲突场景（如行人横穿、刹车、切入、变道、转弯、交叉路口危险事件），投影3D边界框到各相机平面获得候选黄金视图，再通过人工验证确保问题可回答、黄金视图唯一且确凿。

    1. **视图选择**：输入六张视图，模型仅预测黄金视图（或NONE表示无足够证据）。
    2. **Oracle QA**：输入黄金视图图像，模型回答问题（隔离推理能力）。
    3. **联合预测**：输入六张视图，模型同时预测黄金视图和答案（测试端到端接地）。
  - **答案评估**：多项选择使用精确匹配（Exact Match）；自由形式答案使用一个LLM评判器（LLM-as-a-judge）进行语义等价评分。

## 6. 主要结论与发现

- **视图选择困难**：最强专有模型Claude达到82.6%，而开源模型Qwen2.5-VL仅12.6%，接近随机。
- **Oracle到Joint的显著下降**：所有模型在联合预测中准确率大幅低于Oracle QA（例如Claude Oracle MC 89.3% → Joint MC 73.2%），表明视图识别是端到端接地的主要瓶颈。
- **错误视图+正确答案普遍**：在732次多项选择试验中，有192次（约26%）出现了选错视图但答案正确的情况，说明仅凭答案正确性会严重高估grounding能力。
- **自由形式更难**：Free格式在所有设置下均低于多项选择，表示无约束生成引入额外挑战。
- **模型存在前视图偏好**：常过度选择CAM_FRONT，即使关键证据在侧方或后方。
- **未见视图的拒绝能力差**：即使问题无法由任何视图支持，模型也未能正确选择NONE。

## 7. 优点

- **创新性评估视角**：首次将“视觉证据来源识别”作为显式评估目标，补足了仅看重答案准确性的缺陷。
- **三种评估设置的设计精巧**：视图选择、Oracle QA、联合预测形成完整诊断链路，可分离不同层次的故障。
- **数据构建严格**：自动冲突匹配+人工验证，确保黄金视图的唯一性和答案的可回答性；包含“无支持”样本以测试拒绝能力。
- **覆盖多种推理类型**：因果、反事实、意图预测，不仅限于物体识别。
- **评估方式稳健**：同时使用精确匹配（MC）和LLM评判（Free），避免单一度量偏差。

## 8. 不足与局限

- **基准规模小**：仅122个QA对，作为诊断工具而非训练/基准测试平台，统计稳定性受限于样本量。
- **单黄金视图假设**：现实场景中可能需多视图联合证据，当前设计无法评估多视图融合能力。
- **数据偏差**：冲突中心场景来自特定挖掘流水线，不能代表一般驾驶VQA场景；NuScenes本身存在场景偏差。
- **LLM评判噪声**：自由形式答案的评估依赖LLM裁判，可能引入评估偏差和不一致性。
- **仅使用相机图像**：排除LiDAR、雷达和BEV，限制了与实际自动驾驶系统的关联性。
- **可能存在数据污染**：NuScenes作为公开数据集，模型预训练中可能见过相关内容，影响绝对性能估计。
- **未提供训练/微调设置**：只做零样本评估，无法判断模型经过专门训练后能否提升。
