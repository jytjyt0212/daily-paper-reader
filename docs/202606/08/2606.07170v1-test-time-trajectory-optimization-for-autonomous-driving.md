## 摘要
端到端的自动驾驶规划器通常生成一组候选轨迹，为每条轨迹评分，并返回得分最高的候选轨迹。然而，评分仅在生成候选轨迹之后应用，无法影响轨迹集合：无论评分器质量如何，候选轨迹集的薄弱都会限制规划性能。我们转而将评分器视为学习到的轨迹级奖励函数，并搜索最大化该奖励的轨迹。我们的方法TOAD在测试时运行交叉熵方法，并以规划器的候选轨迹作为热启动。它不需要重新训练，对现有规划器即插即用。在六个基础规划器上，TOAD在NAVSIM-v1（94.7 PDMS）、NAVSIM-v2（56.3 EPDMS）和闭环HUGSIM基准测试中均提升了结果。代码将通过项目页面公开：https://valeoai.github.io/TOAD/。

## Abstract
End-to-end planners for autonomous driving typically generate a set of candidate trajectories, score each one, and return the highest-scoring candidate. However, the scorer is applied only after the proposals are generated and cannot influence the set of trajectories: a weak set of candidates limits planning performance regardless of the scorer's quality. We instead treat the scorer as a learned trajectory-level reward function and search for trajectories that maximize it. Our method, TOAD, runs the Cross-Entropy Method at test time, warm-started from the planner's proposals. It requires no retraining and is plug-and-play for existing planners. Across six base planners, TOAD improves results on NAVSIM-v1 (94.7 PDMS), NAVSIM-v2 (56.3 EPDMS), and the closed-loop HUGSIM benchmark. The code will be made publicly available via the project page: https://valeoai.github.io/TOAD/.

### 1. 核心问题与整体含义（研究动机和背景）

- **现有范式瓶颈**：当前端到端（E2E）自动驾驶规划器普遍采用“生成候选集 → 评分 → 选最优”的流水线。但**评分器仅用于对固定候选集排序，无法参与或优化候选集的生成**。若候选集本身质量差（如全部不安全和低效），无论评分器多精准，最终输出仍受限于弱候选集。
- **作者洞察**：评分器本质上是一个**学习到的轨迹级奖励函数**，应能作为优化目标来引导搜索，而非仅作一次性排序。现有方法浪费了这一潜力。
- **核心目标**：证明通过**测试时搜索**（test-time search）可以绕过候选集瓶颈，将评分器用作奖励函数，在连续轨迹空间中寻找更优解，无需重新训练。

### 2. 方法论：核心思想、关键技术细节、算法流程

- **核心思想**：将冻结的评分器 \(S(\tau; o, g)\) 视为奖励函数，在测试时使用**交叉熵方法（Cross-Entropy Method, CEM）** 在轨迹空间（实际为控制空间）中迭代搜索，以最大化包含奖励和正则项的联合目标 \(J(u)\)。

- **关键技术细节**：
  1. **控制空间搜索**：为避免直接采样轨迹导致动态不可行，采用**逆向自行车模型**将轨迹映射为控制序列 \(u = (a_t, \omega_t)\)（纵向加速度和偏航率），再从控制序列通过自行车模型滚动生成轨迹，保证平滑性和可执行性。
  2. **信任区域约束**：
     - **锚定项** \(C_{\text{anchor}}(u) = \|u - u_{\text{base}}\|^2\)，惩罚偏离基础规划器选定轨迹的控制序列。
     - **舒适度正则项** \(C_{\text{comf}}\)，直接对符合运动学约束（加速度、 jerk 等）的硬件限制进行闭式惩罚。
  3. **CEM 迭代流程**：
     - 初始化：均值 \(\mu_0 = u_{\text{base}}\)（基础规划器的轨迹），标准差 \(\sigma_0\) 由基础规划器候选集的标准差乘以缩放因子 \(\beta<1\) 确定。
     - 每轮 \(k\)：从 \(\mathcal{N}(\mu_k, \text{diag}(\sigma_k^2))\) 采样 \(M\) 条控制序列 → 滚动生成轨迹 → 使用联合目标 \(J(u)\) 评分 → 选取得分最高的 \(E\) 个作为精英 → 更新高斯分布 \(\mu_k = \text{mean}(E_k), \sigma_k = \text{std}(E_k)\)。
     - 最终：输出 \(\tau_{\text{mean}} = BM(\mu_K, v_0)\) 与原始 \(\tau_{\text{base}}\) 中最大化 \(S - \lambda_c C_{\text{comf}}\) 的轨迹（锚定项在最后比较时去掉）。

- **评分器选择**：TOAD 要求评分器在**超出训练时候选集分布**的轨迹上仍保持准确。研究发现，基于**固定词汇表**训练的评分器（如 GTRS、SparseDriveV2）在此任务中失效，而 DrivoR 的**分离评分器**（disentangled scorer）因训练时需评估自由解码的轨迹，泛化能力良好，是唯一可用的奖励函数。

- **公式概要**：
  \[
  J(u) = S(BM(u, v_0); o, g) - \lambda_a \|u - u_{\text{base}}\|^2 - \lambda_c C_{\text{comf}}(u)
  \]

### 6. 主要结论与发现

- **搜索优于重排序**：TOAD 的搜索能发现候选集之外更优的轨迹，而单纯用较强评分器重排序并不总是提升性能（甚至可能下降）。
- **评分器泛化是关键**：只有**在训练时未过拟合固定词汇表**的评分器（如 DrivoR）才能在搜索中作为可靠奖励函数；固定词汇评分器在 off-proposal 区域表现差，导致搜索失败。
- **显著提升**：
  - NAVSIM-v1：所有 6 种规划器 PDMS 均有提升，DrivoR 达 94.7（接近人类 94.8）。
  - NAVSIM-v2：提升从 2.3% 到 43.6%，DrivoR+TOAD 达到 56.3 EPDMS，接近上界 PDM-Closed（56.6），**新 SOTA**。
  - HUGSIM：在多个数据集上安全性和舒适度提升，HD-Score 在 nuScenes 上提高 10.2 点。
- **弱规划器获益更大**：越差的规划器通过搜索提升幅度越大（iPad+43.6%），强规划器（DrivoR+3.1%）接近天花板，说明 TOAD 能有效压缩规划器之间的性能差距。

### 7. 优点（方法/实验设计亮点）

- **即插即用，零成本**：无需重新训练，可直接应用于任意现有规划器；推理开销极小（约 2-20 ms）。
- **框架简洁且有理论启发**：将评分器从“排序工具”重新定义为“可优化目标”，揭示了 E2E 规划中一个被忽视的设计缺陷。
- **控制空间建模**：通过自行车模型确保运动学可行性，避免采样无意义轨迹，同时方便施加舒适度约束。
- **信任区域机制**：通过锚定项限制搜索范围，防止评分器在不可靠区域产生奖励黑客（reward hacking）。
- **实验设计严谨**：不仅报告聚合指标，还详细展示各项子指标变化（如安全性与前进的trade-off），并通过消融实验逐一验证设计动机。

### 8. 不足与局限

- **依赖特定评分器**：目前只发现 DrivoR 的分离评分器能可靠工作；对固定词汇评分器，搜索反而会降低性能。这限制了方法的即插即用性——用户必须搭配一个泛化良好的评分器。
- **需要基础规划器提供候选集**：TOAD 的热启动依赖基础规划器输出轨迹和候选集；若只有单轨迹输出（无候选集分布），仍可用（通过零初始化），但性能略逊。
- **搜索能力有限**：CEM 只在信任区域内探索，无法彻底重写轨迹；若基础规划器给出的起始点完全错误，搜索可能无法恢复正常。
- **闭环性能的抵消**：在 HUGSIM 上，虽然安全性和舒适度提升，但路由完成率（RC）有时下降，表明策略变得更保守，可能不适合所有场景。
- **计算开销的冗余**：当评分器作为外部模块时（不是内建于规划器），需要独立运行一次感知骨干网络，造成约 100 ms 的双重计算，可通过架构整合消除。
- **缺乏更广泛的评分器比较**：仅测试了三种固定词汇评分器和 DrivoR，未涵盖其他可能的泛化型评分器（如基于世界模型或 RL 的 reward 模型）。
